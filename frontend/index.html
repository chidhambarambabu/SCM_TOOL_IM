GitFlow Branching Architecture

Formal branching strategy ensuring production stability and controlled concurrent development.

main

Protected

Stores official, audited production releases. Direct commits are restricted. All code merges originate from audited release or hotfix branches.

Current Tag: v1.0.0

develop

Integration

Core integration branch where completed sprint user stories and approved change requests merge after peer code review.

Sprint 1 - 6 Complete

feature/*

Development

Created from develop for new feature development. Merged back via Pull Request after passing automated CI tests.

e.g. feature/food-donation-module, feature/ai-prediction-engine

bugfix/*

Resolution

Used to fix identified defects or implement approved Change Requests affecting integration.

e.g. bugfix/fix-pickup-scheduling (CR-003)

release/*

Release Prep

Used for final stabilization, documentation baselining, and FCA/PCA audits before tagging production.

e.g. release/v1.0.0

hotfix/*

Urgent

Branches directly off main to resolve urgent production issues, then back-merged into develop and main.

e.g. hotfix/security-patch-auth
